# MORO 分支：功能与差异

> [!WARNING]
> **这个项目包含 NSFW（成人向）内容。**
>
> NSFW 只对 18 岁及以上角色、且好感度达到「亲密」档时开放；未成年角色永远没有成人内容。相关开关由用户自己控制。
>
> 恋爱和成人内容已经拆成两个开关：能不能发展恋爱关系由设置里的「允许PLove」控制，NSFW 只控制露骨内容。
>
> 角色由大语言模型扮演，**部分情况下可能出现 OOC（出戏）**：忘记设定、语气漂移、把 NSFW/ASMR 情境演得过火，或说出不符合原作关系的台词。这个项目是个人 fork，不是官方作品，也不保证每一句都符合原作。

这是 [Eidolon-SC](https://github.com/Sallyn0225/eidolon-sc) 的 MORO 分支。  
它在原版「和 283 事务所偶像对话」的基础上，整合并改写了一些社区玩法，重点是把**群聊、恋爱、成人内容、ASMR 通话、记忆范围、自动日程和提示词控制**做成一套完整体验。

上游原有的安装、模型配置、登录、部署和大部分基础功能仍然适用；下面只写这个分支相对原版的主要差异。

---

## 群聊系统

- 可以把多位偶像拉进一个群，让她们自己聊。
- 角色按相关度接话，不保证每个人都说；用户只是群里的普通成员，不是主持人。
- 支持：
  - 拉群、改群名、增加/移除成员
  - 抛话题
  - 群聊开关
  - 解散群，历史记录保留
  - 群聊历史按话题分段
- 可选的「群聊上下文互通」：
  - 私聊时参考最近活跃的一个群
  - 群聊时参考相关成员的私聊
  - 只取最近半小时、最近五轮中文内容，不逐条复述
  - 默认关闭，避免私聊和群聊互相污染
- 群聊的重点不是「用户和每个角色轮流说话」，而是让偶像之间形成自己的对话场。

## NSFW / 成人内容

- 项目明确包含 NSFW 内容，但它是**可选开关**，不是默认全部打开。
- 成人对话：
  - 只对 18 岁及以上角色开放
  - 只在好感度「亲密」档开放
  - 未成年角色永远不开放
- 成人通话语音：
  - 成人对话的日语台词可以带气息、呼吸等配音提示
  - 让通话里的表现更接近成人情境
- 照片、剧情和通话仍然受角色设定与安全边界限制；NSFW 不等于所有越界要求都会被接受。
- 因为角色由模型扮演，成人场景里也可能出现 OOC、节奏失控或不符合人设的表现。

## 允许PLove

- 开关位置：**设置 → 聊天设置 → 允许PLove**，在「群聊上下文互通」上面。
- 恋爱和成人内容彼此独立：
  - **允许PLove 关闭**：使用全年龄关系边界，不进入恋爱；即使 NSFW 开启，也不会进入成人内容。
  - **允许PLove 开启 + NSFW 关闭**：可以亲近、暧昧、恋爱，但不写露骨性内容。
  - **允许PLove 开启 + NSFW 开启**：可以进入成人内容，但仍受年龄和「亲密」档限制。
- 年龄限制始终独立生效：
  - 15 岁以下：不进入恋爱，也没有性内容。
  - 15–17 岁：可以恋爱、暧昧，但没有性内容。
  - 18 岁及以上：性内容再由 NSFW 开关决定。
- 已应用到普通聊天、群聊、通话、搭话、日记和纪念品；不会因为只开了 NSFW 就自动允许恋爱。
- 新用户默认关闭；已有用户在升级时保留原本的恋爱状态。

## ASMR 模式通话

- 通话可以切换到 ASMR 模式：
  - 角色在耳边轻声、慢慢地说
  - 话题可以比普通通话更放松
  - 支持环境音
- 环境音可以：
  - 关闭
  - 使用上次选中的环境音
  - 自动按时间、季节和聊天内容挑选
- 语音优先：
  - 文字会等整句 TTS 解码并开始播放后再出现
  - 避免「文字先跳出来、声音还没开始」的割裂感
- ASMR 是通话模式，不是单独的文字聊天模式。

## 私有、群组与共享记忆

- 记忆不再只有「所有人共享」一种：
  - **私密**：只有记下这条记忆的角色会想起
  - **群组**：同一组合，或设定的家人关系内共享
  - **共享**：所有角色都可以想起
- 每条记忆保留来源角色；其他角色提起时，会以「听某某说」的口吻转述。
- 用户可以在设置的「记忆」里：
  - 查看全部记忆
  - 按角色查看她现在能想起的记忆
  - 修改记忆范围
  - 编辑记忆文本
  - 删除单条或清空全部
- 被新信息取代的旧记忆会标记为「已被取代」，不再被想起；删除取代它的新记忆后可以恢复。
- 记忆和对话历史分开：删掉一段历史对话，不会自动删掉她在那段里记下的事。

## 提示词优化

这个分支对提示词和上下文做了较多稳定性处理，重点是让角色「接着说」而不是「重复上一句」，同时减少格式事故：

- 最近 6 小时内角色自己的最后一句话会放到末尾 assistant 消息，事件、礼物、纪念品和搭话提示进入 system 区。
- 回复的日语 / 中文字幕按片段校验：
  - 无效片段不会显示，也不会送进语音合成
  - 有效片段保留
  - 单个片段失败时只修复该段
  - 无法恢复时给可读的回退文本，不整条回滚
- 礼物、纪念品、未接来电和事件提示按发生顺序放入上下文，不容易被历史长度截掉。
- 照片使用独立的 JSON 规划，不再依赖聊天提示词回退；会校验场景和生图 tag 数量。
- 纪念品名称限制为物品本身，不再堆「手作的」「手折的」这类修饰。
- 仍然可能出现模型不按提示词执行的情况；这些处理是降低概率，不是保证。

## 自动日程

- 每位角色每天自动生成一份大概日程：
  - 3–6 段
  - 起床、睡觉和洗澡按作息自动协调
  - 包含工作、课程、学校、LIVE、休息和私人安排
- 支持组合外景、单人外景和联合外景：
  - 外景会离开东京、当天来回
  - 联合外景显示同行组合名，例如「和 SHHis、illumination STARS 一起」
  - 外景照片和纪念品会使用同行的真实信息
- 日程会受当天的小变数影响，例如临时加练、下雨、路上发现小店、突然想吃某样东西。
- 日程文字以 30 字为目标，但解析上限放宽到 40 字，避免完整句子被截成半个词。
- 「日程安排」面板会显示起床、各段安排、洗澡、睡觉、外景地点和同行组合。
- 日程是「她今天大概在做什么」，不是强制剧本；对话里她可以临时改变，但大方向仍以日程为参考。

## 礼物与纪念品

- 礼物分类扩展为：

  ```text
  food / drink / flower / trinket / fashion / care
  ```

- 新增礼物包括漫画单行本、零钱包、发夹、胸针、围巾、香薰蜡烛、护手霜、茶叶礼盒、香水、入浴剂、多肉植物、插花、水晶摆件和 MP3 播放器。
- 角色喜欢礼物的上限提高到 5 件。
- 礼物兑换界面统一按售价排序，买卖两种模式使用同一顺序。
- 礼物插画统一为 512×512 WebP、透明背景、柔和平涂风格。
- 纪念品仍然由角色在特定场合送出：
  - 场景、生日、纪念日、回礼、约定、旅行 souvenir、节日等
  - 旅行纪念品只有在当天真的有外景 slot 时才会触发
- 礼物和纪念品都会进入对话提示，让她之后的回复知道自己收到了什么、送出了什么。

## 通话、照片与酒馆

- 通话支持时长和回合上限，默认单次 10 分钟、40 回合。
- 未接来电会立即出现在对话里，并自动滚到底部。
- 酒馆语音按句合成后拼接，减少不必要的停顿。
- 照片支持独立规划、重试和同行判断；`others` 中同一角色只保留一次。
- 好感度的 hurt 从最后一次伤害起每小时减少 1 点，新伤害会重置计时并累加。
- 发送消息后强制滚到对话底部，接近微信、QQ 的体验。

## 适合谁

这个分支适合：

- 想和角色进行**群聊**，看偶像之间自己接话的人
- 想单独控制**恋爱关系**，不想为了恋爱打开 NSFW 的人
- 想要 **NSFW 成人对话 / 成人通话**，并且接受这是模型扮演、可能 OOC 的人
- 想要 **ASMR 通话**和环境音的人
- 想区分 **私密 / 群组 / 共享记忆** 的人
- 想让角色有**自动日程、外景和联合外景**的人
- 想继续使用原版部署方式，但希望玩法和提示词更完整的人

如果你只想要原版干净、稳定的对话体验，建议使用上游项目；这个分支的恋爱开关、NSFW、ASMR 和自动日程会带来更多模型行为差异。

## 部署

这个分支仍然使用：

```text
后端：FastAPI + Python 3.11
前端：Next.js 16 + React 19
数据库：SQLite
容器：Docker Compose
```

后端 Python 改动用 overlay 快速上线；前端改动需要重新构建 Next.js 产物。具体见仓库的部署文档和 `.agents/skills/deploy-server/`。
