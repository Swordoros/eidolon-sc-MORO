# Eidolon-SC / MORO fork

这是 [Eidolon-SC](https://github.com/Sallyn0225/eidolon-sc) 的 MORO 分支，保留了 283 事务所的对话、通话、剧情回忆和跨角色记忆，并在这套基础上做了下面这些功能调整。

上游原有的安装、模型配置和部署说明仍然适用；本文件只记录这个分支相对上游的主要改动。

---

## 日程

- 角色每天自动生成 3–6 段日程，包含起床、睡觉、洗澡和当天的小变数。
- 支持组合外景、单人外景和联合外景：
  - 外景会离开东京、当天来回，并排进当天行程。
  - 联合外景会显示同行组合名，例如「和 SHHis、illumination STARS 一起」，不再逐个列出成员。
  - 外景和回程会记录同行成员，用于外景照片和纪念品判断。
- 日程文字提示词目标仍是 30 字，但解析器上限放宽到 40 字：
  - 不再因为一个 31 字的完整句子被截成半个词。
  - 完整表达优先，超过 40 字才截断。
- 日程里不会把洗澡写成一个 slot；系统根据睡觉时间自动安排洗澡。
- 联合外景、外景回程和同行信息会显示在「日程安排」面板中。

## 对话与提示词

- 最近 6 小时内角色自己的最后一句话会移到末尾的 assistant 消息，后面的礼物、纪念品、搭话等事件进入 system 提示，避免历史截断后角色重复上一句。
- 回复的 ja / zh 分段做段级校验：
  - 无效片段不会显示，也不会送进 TTS。
  - 有效前缀保留，单个片段失败时只修复该段。
  - 无法恢复时给可读的回退文本，不会整条回复回滚。
- 礼物、纪念品和事件提示按发生顺序放在合适的位置，不会因为历史长度被截掉。
- 发送消息后强制滚到对话底部，行为接近微信、QQ。
- 未接来电事件会立即出现，并自动滚到底部，不需要刷新。

## 礼物与礼物商店

- 礼物分类从 4 类扩展到 6 类：

  ```text
  food / drink / flower / trinket / fashion / care
  ```

- 礼物目录目前有 34 件，新增了：
  - 漫画单行本、零钱包、发夹、胸针、围巾、香薰蜡烛、护手霜、茶叶礼盒
  - 香水、入浴剂、多肉植物、插花、水晶摆件、MP3 播放器
- 「首饰」改名为「项链」，并归入 `fashion`，避免和新的礼物分类混淆。
- 角色喜欢礼物的上限从 3 件提高到 5 件。
- 礼物兑换界面统一按 **售价** 排序，买卖两种模式都使用同一顺序：
  - 当前为售价从低到高。
- 礼物插画使用 512×512 WebP、透明背景，统一为柔和扁平 2D 风格。
- 新增礼物流程技能：

  ```text
  .agents/skills/gift-catalog/SKILL.md
  ```
- 新增礼物的喜欢关系仍需在对应角色的 `facts/<角色>.sources.md` 里补出处；部分新增关系目前标记为「具体剧情出处待补」。

## 纪念品

- 纪念品名称提示词收紧：
  - 只写物品本身，不加「手作的」「手折的」这类修饰。
  - 工艺、材质和颜色写在 `look` 里。
- 纪念品分页/柜子、图片重画、删除和未读提示沿用上游功能。
- 外景纪念品只会在当天真的有外景 slot 时触发，不会仅凭日程的 trip 字段产生。

## 通话与酒馆

- 通话有单次时长和回合上限，默认单次 10 分钟、40 回合。
- 未接来电会作为对话事件立即显示。
- 好感度的 hurt 从最后一次伤害起按每小时 1 点衰减，新的伤害会重置计时并累加。
- 酒馆语音等整句 TTS 解码并开始播放后才显示文字，避免文字先于声音出现。
- 酒吧语音按句合成后拼接，减少额外停顿。

## 照片

- 照片使用独立的 JSON 规划，不再依赖聊天提示词回退。
- 规划会限制 `place` 标签数量和生图 tag 数量，超量会校验并修正。
- `others` 中同一个角色只保留一次；`scene` 和 `others` 可以同时出现同一角色。
- 外景照片的同行判断会使用日程里的同行成员；联合外景不会重复生成同一份内容。

## 界面与其他

- 礼物商店按分类筛选，新增「穿戴」和「护理」。
- 日程面板显示外景地点和同行组合。
- 发送消息自动滚到底部。
- 照片、纪念品、礼物和通话的若干提示词与格式做了稳定性和可读性修正。

## 开发与部署

这个分支的部署方式仍然是：

```text
后端：FastAPI + Python 3.11
前端：Next.js 16 + React 19
数据库：SQLite
容器：Docker Compose
```

后端改动可以使用 Python overlay 快速上线；前端改动需要重新构建 Next.js 产物。具体步骤见仓库的部署文档和 `.agents/skills/deploy-server/`。
